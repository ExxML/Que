# Detection research and investigation ledger

Reviewed 2026-11-14. This is an expanding threat inventory, not a proof that all possible detection methods have been exhausted. A hypothesis, implemented probe, executed probe, reproduced effect, and demonstrated identification are different outcomes. No literature result below is reported as a measured Que exposure.

## Additional browser observation channels

| Channel and primary source | Executable investigation | Required controls and unresolved conditions |
| --- | --- | --- |
| [System idle detection](https://wicg.github.io/idle-detection/) exposes system user/screen state after permission. | `research.idle`, the **System idle state** button and `idle-state` events. Observe at least 65 seconds, then press a suppressed chord while the page remains focused. | Compare idle→active with page key events for Que absent, visible and hidden. An idle transition without a key event may indicate activity elsewhere; it does not identify Que. The 60-second minimum threshold is enforced in the protocol. Permission denial and missing states cannot pass. |
| [Compute Pressure](https://www.w3.org/TR/compute-pressure/) provides coarsened device-pressure observations. | `research.pressure`, **CPU pressure**, actual `PressureObserver` callbacks. | Two independently randomized batches, transcription and unrelated CPU controls. Foreground eligibility, sampling suppression, coarsening and platform support can limit sensitivity. A constructor existing is insufficient evidence. |
| [EyeDropper](https://wicg.github.io/eyedropper-api/) returns a user-selected screen color, with transient activation and deliberate selection. | `research.eyedropper`, **Select a screen pixel**. Compare absence, an ordinary native positive control and Que at the same documented physical coordinate; repeat exclusion settings and surfaces. | Retain physical selection video: the returned value provides no coordinate. Investigate whether capture affinity applies to this path; the specification alone does not establish a bypass. This is not passive screen scraping. Cancellation is incomplete. |
| [Window Management](https://www.w3.org/TR/window-management/) exposes permitted screen details and changes. | `research.screens`, **Display details and changes**, screen/current-screen listeners and visual-viewport listeners. | Move the browser and Que independently, change scaling/topology, and run absent controls. Geometry changes do not by themselves identify an application. Native display snapshots independently validate the selected DPI configuration. |
| [Web Audio](https://www.w3.org/TR/webaudio/) includes rendering-thread processing and output timestamps. | `research.worklet`, **Audio rendering continuity**, `audio-worklet.js`, quantum counts/RMS/delivery times and output timestamps. | Both browser/Que acquisition orders; actual microphone and loopback transcripts; speaker/headset and sound/silence controls. Main-thread RMS samples alone cannot exclude rendering or device disruptions. Processor failures invalidate negatives. |
| [WebGL timer-query specification](https://registry.khronos.org/webgl/extensions/EXT_disjoint_timer_query_webgl2/) exposes supported GPU elapsed-time queries. | `research.gpu`, **GPU timing**, synchronized wall-clock measurements and separate GPU timer samples. | Compare movement, rendering, streaming and transcription with unrelated rendering loads. Record extension availability and disjoint/context-loss events. A wall-clock fallback does not establish GPU-timer coverage. |
| [FROST research paper](https://hannesweissteiner.com/pdfs/frost.pdf) investigates OPFS storage contention. | `research.storage`, bounded synchronous OPFS random reads in `storage-worker.js`; default 64 MiB, adjustable 1–2048 MiB within one quarter of remaining origin quota. | The published evaluation covers macOS/Linux, not a Que-on-Windows result. Its sustained SSD measurements require shared physical storage and a working set exceeding cache. Our bounded fixture can remain cached. Establish actual I/O sensitivity with owned load controls and different budgets; a negative cached result cannot exclude SSD contention. The worker deletes only its uniquely named fixture on **Stop**. |
| [Browser cache-side-channel research](https://arxiv.org/abs/2103.04952) shows that reduced timer/script capabilities alone do not settle microarchitectural inference. | `research.memory`, a 32 MiB worker traversal, plus separate ordinary and `--cross-origin-isolated` runs. | This is a coarse contention probe, not a reproduction of the paper's cache attack or a trained classifier. Hardware-specific eviction sets, CSS-only variants and held-out application classification remain unverified research coverage. Timer resolution, working set and unrelated load must accompany results. |
| [Granted file-system access](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access) permits observing shared files. | The directory probe verifies the staged fixture marker, recursively reads metadata and up to 64 KiB per file, and polls during actions. It records sizes, modification times and prefix hashes. | Exercise history/screenshot/model writes and create/delete/rename transitions. Encrypted configuration contents are not exported. Depth/entry limits produce probe errors rather than coverage passes. The optional [File System Observer API](https://developer.chrome.com/blog/file-system-observer) is feature-detected; notification behavior remains separate from implemented polling. |
| [Chrome local-network guidance](https://developer.chrome.com/docs/modern-web-guidance/guides/security/local-network-access) and [Edge guidance](https://learn.microsoft.com/en-us/deployedge/ms-edge-local-network-access) distinguish source origins and permissions. | `network-origin-test.html` and `stealth/network_origin.py`: HTTPS-origin fetch/WebSocket requests to one explicitly owned, read-only loopback endpoint; running/stopped controls and exported browser JSON. | Host the fixture on a permissioned HTTPS origin and keep normal security enabled. Localhost-origin success is not public-origin coverage. Test actual browser versions, prompt/granted/denied states and candidate owned application listeners separately. No port scan or arbitrary endpoint probing is implemented. WebTransport needs an owned HTTP/3 service and remains unverified. |

Clipboard text/HTML/image format and hash observations, capture cursor settings, track labels, permission changes, long-animation-frame/event timing, device changes, focus polling and worker timing are also retained. These observations are not all identity signals. Add a declared classifier and held-out controls before claiming identification; the current suite makes no such claim.

## Investigated technical limits and next experiments

| Limitation | Investigation and concrete continuation |
| --- | --- |
| Native positive controls are absent from an isolated tab/window source. | The [Screen Capture specification](https://www.w3.org/TR/screen-capture/) distinguishes source surfaces and cursor behavior. The suite now supplies a DOM positive control for isolated captures and requires a native control for monitor captures. Continue the actual overlay exposure test after source-appropriate calibration; do not stop at the missing native control. Record source settings and never transfer calibration between sources. |
| Short-lived pixels between captured frames. | Removed the artificial 10 Hz throttle and blocking image-upload wait. Every delivered decoded callback is analyzed, single-pixel/one-level changes are retained, and changed images are queued. Backpressure, geometry changes and missing decoded callbacks invalidate negative evidence. Still report actual frame cadence and dropped/presented counts: an API cannot prove what happened between delivered frames. Repeat first-paint/popups at varied phases. |
| Pixel noise and changing backgrounds. | Calibration requires ten exactly unchanged negative frames, saved baseline/positive/restored-negative PNGs and a live beacon. Investigate source mapping, scaling, cursor inclusion and unrelated movement. Do not increase thresholds or mask Que's footprint to obtain a pass. Changed pixels show an effect; attribution requires controls and artifact review. |
| Whole-window capture versus physical topmost state. | Capture-excluded images cannot establish physical visibility. Pair native z-order/rectangle episodes with a physical camera/video and a reviewed receipt, including very brief occlusions. The raising timer receives no grace period. A newly reproduced native query-error path returns `True`; `failure.topmost-query-error` remains FAIL. |
| Onefile runtime path discovery. | Que derives settings/history/cache paths from module `__file__`. [Nuitka documentation](https://nuitka.net/user-documentation/common-issue-solutions.html) distinguishes onefile extraction paths from executable paths. The runner redirects temporary storage and now inventories files under its private extraction tree as well as the staged cache. Observe writes before/during/after two launches, match the exact executable hash, verify where settings and screenshots actually land, and verify cleanup/restart behavior. Do not replace missing runtime-path evidence with a source-only result. A local `que.dist/que.exe` candidate exists; its release provenance and physical behavior are not established. |
| Display setup unavailable in this session. | The observed workstation has one 2560×1600 monitor at 150%, which satisfies neither mandatory 100% nor mixed-DPI setup. Physical-configuration receipts now require display snapshots that match the declared layout plus physical visual evidence. A dropdown or typed note cannot override the mismatch. Use the specified hardware configurations for the remaining matrix. |
| Statistical power and observer interference. | Mean, p95 and standard-deviation comparisons use two counterbalanced batches, family-wise correction and a preregistered ±1 ms equivalence bound. Negative results need effective matched generic load controls and a stable sham. GPU, audio, memory and storage probes are themselves workloads: compare identical enabled probes and retain raw intervals. The generic controls do not establish SSD cache bypass or train an application classifier. |
| Unexecuted code and platform-specific paths. | `operations.json` tracks routines, branches, exception handlers and background calls. `native/execution-gaps.json` records which entry/body lines the controlled regression run never reached. Every failure/background site has an independently reported guided scenario. These are declared contracts, not completed tests. Remaining gaps stay INCONCLUSIVE; line execution also does not prove browser protection or exhaustive condition/combination coverage. |

The manifest's pairwise state combinations and selected high-risk triples are a practical starting set, not all possible concurrency schedules. Races discovered during execution must receive their own retained reproducer. Unsupported hardware APIs, browser UI restrictions, source-selection choices and unperformed matrix cells must remain visible in the report.

## Follow-up: framework-created transient windows

The unattended handoff investigation found a separate visible window with affinity 0 during three openings of the production settings combo on Qt 6.9.0, despite successful exclusion of the final popup. The sampled spans were 148.91–152.03 ms. A separately labeled animation-disabled control removed the transient. This is native evidence requiring actual browser capture confirmation, not a completed website exposure test.

The primary [Qt 6.9.0 combo implementation](https://raw.githubusercontent.com/qt/qtbase/v6.9.0/src/widgets/widgets/qcombobox.cpp) invokes a 150 ms scrolling effect. The [effect implementation](https://raw.githubusercontent.com/qt/qtbase/v6.9.0/src/widgets/widgets/qeffects.cpp) creates a separate top-level widget displaying the popup pixmap. This supports investigating animation windows independently of the intended popup handle. Extend capture experiments to menu/tooltip effects, short-lived handles and repeated openings; protecting a steady-state popup alone is insufficient evidence. See [CAP-001 in the repair handoff](STEALTH_REPAIR_HANDOFF.md#cap-001--combo-opening-creates-an-unexcluded-transient-window) for retained controls and reproduction.
